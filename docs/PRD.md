# FasType 开源版产品需求文档（PRD）

> 文档状态：Draft v0.3  
> 更新日期：2026-07-21  
> 产品形态：面向个人、纯前端运行的轻量 Markdown 写作与排版工具  
> 参考产品：LovType（能力来源参考，不等同于开源版范围）

## 1. 产品概述

### 1.1 一句话定义

FasType 是一个无需账号、没有后端、一次只处理一篇 Markdown 文档的轻量写作工具，帮助用户完成 Markdown 编辑、小红书图片排版、微信公众号排版，以及基于自有 API Key 的轻量 AI 修改。

### 1.2 背景

LovType 已经覆盖项目管理、多文件、AI Agent、知识库、生成任务、会员积分、云存储和多平台发布等完整工作台能力。但对只想快速处理一篇文章的个人用户而言，完整工作台的部署、学习和使用成本偏高。

FasType 不做 LovType 的完整开源复刻，而是抽取最常用、最容易独立成立的一条链路：

```text
打开或新建一篇 Markdown
        ↓
编辑内容，可选使用轻量 AI
        ↓
切换小红书或公众号预览
        ↓
调整样式并导出可发布结果
```

### 1.3 产品定位

- 面向个人使用，而非团队内容生产平台。
- 纯前端、本地优先，可作为静态站点部署，不依赖 FasType 后端或官方云服务。
- 聚焦单篇内容，不提供项目、目录和多文件管理。
- 非 AI 功能始终可用；AI 是可选增强能力。
- 优先保证“写完能带走”，不直接对接平台发布 API。
- 界面尽可能简洁，核心任务在一个工作台内完成。
- “简洁”指信息架构、操作链路和产品范围，不代表降低已纳入功能的视觉还原度；主题选择、排版预览等核心界面应尽可能还原 LovType 的成熟样式。

## 2. 产品目标与非目标

### 2.1 产品目标

1. 用户打开应用后，可以在 30 秒内开始编辑 Markdown。
2. 用户无需登录，即可完成编辑、预览和导出。
3. 同一份 Markdown 可以快速查看小红书和公众号两种发布效果。
4. 小红书内容可以导出为分页 PNG；公众号内容可以复制为兼容公众号编辑器的富文本。
5. 用户可以填写自己的 API Key、Base URL 和模型名，完成基础 AI 改写。
6. 正常编辑和导出全部在浏览器中完成，不上传文章到 FasType 官方服务。
7. 首版同时提供中文和英文界面，并支持浅色、深色主题。
8. 三个主视图都保持实时双栏并可自由调整宽度；小红书和公众号“内容”下的编辑器可在带行号的 Markdown 文本与无行号、仍可直接编辑的 Markdown 预览之间切换。

### 2.2 非目标

MVP 不包含以下能力：

- 用户注册、登录、会员、积分和订单。
- 项目、文件树、文件夹、多文档标签页和团队空间。
- 云同步、跨设备同步、版本历史和多人协作。
- AI Agent、工具调用、联网搜索、知识库和长任务队列。
- AI 图片、封面、思维导图、流程图、卡片等生成工具。
- 小红书或微信公众号的一键发布。
- 官方图片托管、素材库和对象存储。
- 管理后台、运营后台和内容审核后台。
- Next.js Route Handler、Server Action、数据库或其他业务后端。
- 公共分享链接和在线作品社区。
- 移动端原生 App。

## 3. 目标用户

### 3.1 核心用户

#### A. 独立内容创作者

- 使用 Markdown 写作。
- 同一篇内容会分发到小红书和公众号。
- 希望快速预览和排版，不想维护复杂内容系统。

#### B. 开发者与 BYOK 用户

- 有自己的 OpenAI 兼容模型服务或第三方 API。
- 关注内容隐私，不希望文章被默认上传到官方 SaaS。
- 希望直接使用静态站点，或部署到自己的静态托管服务。

#### C. 偶尔写作的轻量用户

- 不需要管理大量文档。
- 主要通过粘贴、打开或拖入一篇 Markdown 开始工作。
- 需要开箱即用的样式模板，而不是复杂的设计系统。

## 4. 核心使用场景

### 4.1 从 Markdown 到小红书图片

用户打开一篇 Markdown，选择小红书视图，调整主题、字号和分页，预览最终卡片并导出全部 PNG。

### 4.2 从 Markdown 到公众号排版

用户打开一篇 Markdown，选择公众号视图，调整标题、正文、引用和代码样式，确认预览后复制富文本，粘贴到微信公众号编辑器。

### 4.3 使用自己的模型轻量改文

用户配置 Base URL、API Key 和模型名，在编辑器中选择一段文字，执行润色、扩写、精简或自定义修改，确认结果后替换原文。

### 4.4 临时写作与恢复

用户直接新建空白文档开始写作。浏览器意外关闭后，再次打开 FasType 时可以恢复上一次未导出的草稿。

## 5. 产品原则

1. **单文档优先**：界面中永远只有一篇正在处理的文档，不引入文件树和多标签页。
2. **内容与样式分离**：Markdown 是内容源，小红书和公众号样式不反向污染正文。
3. **所见接近所得**：预览与导出使用同一套渲染规则，避免预览和最终结果明显不一致。
4. **默认本地化**：文档、样式和模型配置默认保存在本地浏览器；除 AI 请求和远程图片外，不主动发起外部数据请求。
5. **AI 可选且可撤销**：没有 AI 配置不影响编辑和排版；AI 不得未经确认直接覆盖正文。
6. **平台能力独立**：小红书和公众号有各自的预览、设置与导出动作，不强行合并成一个通用导出弹窗。
7. **轻配置**：先提供少量质量稳定的内置模板，再开放必要的字号、颜色和间距调整。
8. **单屏完成**：高频操作直接可见，低频配置使用抽屉或弹窗，不增加多层页面导航。
9. **前端直连**：AI 请求由浏览器直接发往用户填写的 Base URL，不经过 FasType 中转服务。
10. **成品预览与编辑器预览分层**：小红书和公众号左侧始终是平台成品预览，右侧是平台工作台；“文本 / 预览”只切换“内容”下的 Markdown 编辑器本身，固定在编辑器工具栏最右侧，不控制平台分栏，也不进入应用全局顶栏。

## 7. 信息架构与页面结构

MVP 只有一个主工作台和一个设置入口。

### 7.1 主工作台

小红书和公众号始终使用“左成品预览、右工作台”的双栏骨架；“内容”下的编辑器工具栏最右侧提供“文本 / 预览”，只改变编辑器内部的 Markdown 显示。应用全局顶栏只负责平台切换和全局操作。编辑器主视图同样使用双栏：

```text
┌────────────────────────────────────────────────────────────────────┐
│ Logo / 文件名 / 文件操作       小红书｜公众号｜编辑器       中/EN ◐ ⚙ │
├────────────────────────────────────────────────────────────────────┤
│ 内容｜封面/主题/版式/元素/人设                                  │
├───────────────────────────┬─┬──────────────────────────────────────┤
│                           │ │                                      │
│         左侧预览           │┃│        右侧内容 / 样式工作台           │
│                           │┃│                                      │
│  小红书/公众号：默认 33%     │┃│  编辑器工具栏右侧：文本｜预览           │
│  编辑器：默认 50%           │┃│                                      │
│                           │ │                                      │
├───────────────────────────┴─┴──────────────────────────────────────┤
│ 预览状态 / 页数                 字数 / 光标 / AI 状态 / 主导出动作  │
└────────────────────────────────────────────────────────────────────┘
                              ↑
                         可拖动分隔条
```

- 小红书视图左侧始终显示分页卡片预览，默认约占总宽度的 1/3；右侧是“内容 / 封面 / 主题 / 排版 / 元素 / 人设”一级 Tab 工作台，约占 2/3。“文本 / 预览”位于“内容”编辑器工具栏最右侧。
- 公众号视图左侧始终显示公众号文章预览，默认约占总宽度的 1/3；右侧是“内容 / 封面 / 主题 / 排版 / 人设”一级 Tab 工作台，约占 2/3。“文本 / 预览”位于“内容”编辑器工具栏最右侧。
- 编辑器视图左侧显示通用 Markdown 渲染预览，右侧显示源码编辑器，默认比例为 1:1。
- 三个视图的内容编辑器都在工具栏左上角显示 Save 状态图标：有尚未完成本地自动保存的变更时显示橙色，3 秒自动保存完成后恢复普通颜色。
- 三个视图的中间都提供可拖动分隔条，并分别记住用户最后一次调整的比例。
- 平台样式设置直接位于右侧工作台的一级 Tab 下，不增加固定第三栏。

### 7.2 设置抽屉

- AI 配置。
- 本地数据管理。
- 外观设置。
- 关于、开源地址、版本和隐私说明。
- 设置通过右侧抽屉或紧凑弹窗完成，不跳转到独立设置页面。

## 8. 详细功能需求

### 8.1 单文档生命周期

#### FT-DOC-001 新建文档（P0）

- 用户可以创建空白 Markdown 文档。
- 默认文件名为 `未命名.md`，用户可以修改。
- 新建会替换当前工作区内容；如果当前文档有未保存变更，必须先提示保存、下载或放弃。

#### FT-DOC-002 打开文档（P0）

- 支持文件选择器和拖拽导入。
- P0 支持 `.md`、`.markdown` 和 `.txt`。
- 同一时间只加载一个文件；打开新文件前处理当前未保存变更。
- 不支持的编码或文件类型需要给出明确提示，不能静默显示乱码。

#### FT-DOC-003 保存与下载（P0）

- 编辑期间每 3 秒自动保存一次，不提供单独的手动保存按钮。
- 在支持 File System Access API 的浏览器中，用户授权后自动写回原文件。
- 不支持直接写回时，提供“下载 Markdown”作为一致的降级方案。
- 自动保存成功后不显示“已保存”等常驻状态；保存失败使用 Toast 提示。

#### FT-DOC-004 自动草稿（P0）

- 编辑期间每 3 秒自动保存到 localStorage。
- MVP 只保留一份当前草稿，不提供草稿列表。
- 应用异常关闭后，下次打开可以恢复文档内容、文件名、平台样式、上次所在视图和各视图分栏比例。
- 本地草稿不是“已写回原文件”，两种状态必须区分。

#### FT-DOC-005 内容替换保护（P0）

- 新建、打开其他文件、清空本地数据前，若存在未写回/未下载的变更，必须二次确认。
- 页面关闭时，在浏览器允许的范围内触发未保存提示。

### 8.2 Markdown 编辑器

#### FT-EDT-001 基础编辑（P0）

- 提供纯 Markdown 编辑体验，不要求用户在富文本和 Markdown 之间切换。
- 支持中文输入法、撤销/重做、缩进、成对符号和行号。
- 支持常见 Markdown：标题、粗体、斜体、删除线、链接、图片、引用、无序/有序列表、分割线、行内代码、代码块和表格。
- 编辑 10,000 个中文字符的文档时，常规输入不应出现明显卡顿。

#### FT-EDT-002 编辑辅助（P0）

- 工具栏提供常用 Markdown 格式动作。
- 支持搜索与替换。
- 状态栏显示可见文本字数、字符数和当前光标行列。
- 点击格式按钮或使用快捷键后，焦点应回到编辑器。

#### FT-EDT-003 实时同步（P0）

- Markdown 内容变化后，小红书和公众号预览应在短暂防抖后更新。
- 切换视图不得丢失光标前的编辑结果。
- 平台视图读取同一份当前 Markdown，不维护独立正文副本。

#### FT-EDT-004 编辑器双栏视图（P0）

- 编辑器视图左侧是实时渲染预览，右侧是 Markdown 源码编辑器。
- 首次打开默认使用 50% : 50% 的左右比例。
- 用户拖动分隔条时，预览和编辑器应连续响应，不需要松手后才更新。
- Markdown 预览滚动位置与编辑器滚动位置可以独立控制；P1 再考虑双向同步滚动。
- 重新进入编辑器视图时，恢复用户上次设置的比例。
- 预览区 Header 提供“下载长图”操作，将完整 Markdown 渲染结果导出为单张 PNG，不包含 Header 本身。
- 预览区 Header 中间提供 GitHub、Notion、纸张和夜读四种经典主题，切换后即时更新预览与长图导出效果，并记住上次选择。

### 8.3 小红书预览与排版

#### FT-XHS-001 内容解析（P0）

- 仅渲染 Markdown 中明确存在的一级标题。
- 如果没有一级标题，不自动补标题，也不在图片中显示文件名。
- 预览中应区分标题、正文、图片和标签，但不强制向 Markdown 写入平台专用元数据。
- 图片正文与内容正文使用两套独立限制：Markdown 图片正文同时受 5000 字和 20000 字符硬上限约束，任一达到后不得继续增加输入；发布到小红书笔记区域的内容正文上限为 1000 字，不得混用两者的计数或告警。
- 标题限制仅作用于小红书笔记的内容正文标题，与 Markdown 原始标题和封面标题无关。内容正文标题超过 20 字时明确标红，但允许继续输入至 25 字，且不阻止用户导出。

#### FT-XHS-002 卡片预览（P0）

- 将 Markdown 渲染成适合小红书图文发布的竖版卡片。
- 默认画布比例为 3:4，并提供至少一种常用高清导出尺寸。
- 长内容自动分页，预览中展示页码和总页数。
- 所有页面使用一致的主题、边距和基础字体规则。
- 远程图片加载失败时显示占位和来源提示，不能导致整组导出失败。

#### FT-XHS-003 样式设置（P0）

- 右侧工作台提供“内容 / 封面 / 主题 / 排版 / 元素 / 人设”一级 Tab，再在当前 Tab 下展示具体设置。
- 直接复用 LovType 的 7 套内置主题：经典、优雅、海洋、森林、玫瑰、暗夜、深海。
- 支持调整：字体方案、正文字号、行高、内容边距、背景色、正文色和强调色。
- 人设设置中的二维码和页脚序号可分别选择是否在封面展示，两个封面开关默认关闭。
- 设置变更实时反映到预览。
- 提供“恢复当前主题默认值”。
- 样式设置保存在本地，不写入 Markdown 正文。

#### FT-XHS-004 分页（P0/P1）

- P0：根据可用高度自动分页，避免文字被裁切。
- P0：标题、代码块、引用和图片等内容尽量整体放置；无法整体放置时使用可预测的拆分规则。
- P0：图片超过 18 页时将页数状态显示为警告态，并提示发布时会自动转为视频；该提示不阻止继续预览或导出。
- P0：封面未展示页码时不计入页码总数；展示页码时封面作为第 1 页，正文序号顺延。
- P1：支持通过专用 Markdown 注释插入手动分页符，注释不出现在最终内容中。
- P1：支持封面页以及封面标题的单独样式设置。

#### FT-XHS-005 导出（P0）

- 支持把当前全部页面渲染为 PNG，并打包成一个 ZIP 下载；导出当前页时仍下载单张 PNG。
- 文件名包含原文档名和有序页码，例如 `文章名-xhs-01.png`。
- 导出图片与预览的字体、颜色、分页和图片位置应保持一致。
- 全部导出只触发一次 ZIP 下载，避免浏览器拦截连续多文件下载。
- 导出过程展示进度，并允许在失败后重试。

#### FT-XHS-006 分栏工作区（P0）

- 小红书首次打开即显示左侧成品预览与右侧工作台，默认约 33% : 67%。
- Markdown 编辑器位于“内容”Tab；其工具栏最右侧提供“文本 / 预览”切换，不放在工作区 Header 或应用全局顶栏。
- “文本”展示 Markdown 源码与行号；“预览”展示 Markdown 排版、隐藏行号，但仍能在原位置直接编辑并实时回写同一份 Markdown。
- 左侧预览可以独立滚动和切换页面；右侧编辑不因预览操作丢失焦点或内容。
- 样式设置通过右侧工作台顶部的一级 Tab 切换，下方只展示当前分类的具体内容。
- 重新进入小红书视图时，恢复该视图上次设置的比例。

### 8.4 微信公众号预览与排版

#### FT-WX-001 公众号预览（P0）

- 将当前 Markdown 渲染为接近微信公众号文章页的预览。
- 支持标题、段落、各级标题、列表、引用、链接、图片、分割线、表格和代码块。
- 预览容器宽度和文字密度应接近公众号移动端阅读效果。
- 外部链接、复杂表格、代码块等可能被微信编辑器限制的内容应给出提示。
- 公众号 Markdown 正文同时受 10000 字和 40000 字符硬上限约束，任一达到后不得继续增加输入；已导入的超限文档仍须允许删除和缩短。

#### FT-WX-002 样式设置（P0）

- 直接复用 LovType 的 7 套内置主题：经典、优雅、海洋、森林、玫瑰、暗夜、深海。
- 支持调整：字体方案、正文字号、行高、段间距、正文色、强调色、标题样式、引用样式和代码样式。
- 设置变更实时更新预览。
- 提供“恢复当前主题默认值”。

#### FT-WX-003 微信兼容 HTML（P0）

- Markdown 转换结果使用适合复制到微信公众号编辑器的内联样式。
- 不依赖外部 CSS 才能保持核心排版。
- 对微信不稳定或不支持的 CSS 使用降级样式。
- 复制前应完成必要的 HTML 清理，避免带入 FasType 工作台自身的结构和类名。

#### FT-WX-004 复制与导出（P0）

- 主动作是“复制到公众号”，优先写入 `text/html`，同时提供纯文本降级。
- 复制成功后给出明确反馈。
- 用户可以下载完整 HTML 文件用于检查或备份。
- 提供“复制纯文本”作为兼容性兜底。
- 产品文案需要说明：最终效果仍以粘贴到微信编辑器后的结果为准。

#### FT-WX-005 分栏工作区（P0）

- 公众号首次打开即显示左侧成品预览与右侧工作台，默认约 33% : 67%。
- “内容”编辑器工具栏最右侧提供“文本 / 预览”切换，不放在工作区 Header 或应用全局顶栏。
- “文本”展示 Markdown 源码与行号；“预览”展示 Markdown 排版、隐藏行号，但仍能直接编辑并实时更新公众号成品预览。
- 左侧预览和右侧编辑器可以独立滚动。
- 样式设置从右侧工具栏打开抽屉或弹窗，不增加固定第三栏。
- 重新进入公众号视图时，恢复该视图上次设置的比例。

#### FT-WX-006 公众号封面（P0）

- 公众号工作台提供独立“封面”Tab，不把封面设置混入正文主题或人设设置。
- 同一篇文章可分别完成 900×383 横版头图与 500×500 方形缩略图。
- 用户上传一张本地图片后，可按两种比例分别裁剪；原始图片不上传到服务端。
- 标题可自动跟随 Markdown 第一个 H1，也可手动输入；头像和用户名复用全局用户资料。
- 横版预览可显示居中的方形安全区，该辅助线不进入导出图。
- 横版与方形封面可单独下载 PNG，也可打包为一个 ZIP；预览与下载共用同一画面节点。

### 8.5 轻量 AI

#### FT-AI-001 模型配置（P0）

- 用户可以填写：
  - Base URL；
  - API Key；
  - 模型名；
  - 可选的温度和最大输出长度。
- 默认兼容 OpenAI 风格的 Chat Completions 接口。
- API Key 输入框默认遮挡，支持显示/隐藏和一键清除。
- 配置保存在当前站点的 localStorage 中，配置不进入代码仓库、URL 或分析事件。
- 明确提示用户：AI 请求会把相关文本发送到其配置的模型服务商。
- 所有模型请求由浏览器直接调用 Base URL，不经过 FasType 服务端。
- 用户填写的服务必须支持浏览器 CORS；FasType 不提供绕过 CORS 的后端代理。

#### FT-AI-002 连接测试（P0）

- 用户保存配置前后均可发起连接测试。
- 测试结果区分：连接成功、鉴权失败、模型不存在、接口不兼容、跨域/网络失败和超时。
- 错误信息应可操作，例如提示检查 Base URL 是否需要包含 `/v1`，而不是只显示“请求失败”。
- 检测到 CORS 错误时，提示用户在模型服务端允许当前站点来源，或使用允许跨域的兼容服务。

#### FT-AI-003 选中文本操作（P0）

- 选中文字后提供：润色、扩写、精简和自定义指令。
- 请求可以携带选中文本及有限的上下文，但必须避免无必要地发送整篇文章。
- AI 输出以流式方式展示；不支持流式的服务可以降级为一次性结果。
- 操作中可以取消请求。

#### FT-AI-004 结果确认（P0）

- AI 结果不得直接覆盖原文。
- 用户至少可以选择：替换选中内容、插入到选中内容之后、重新生成、复制结果、取消。
- 替换后可以通过编辑器撤销恢复原文。
- AI 返回空内容、Markdown 围栏或额外解释时，应用应保守处理，不应破坏正文结构。

#### FT-AI-005 平台化操作（P1）

- 将选中内容或全文改写为小红书风格。
- 将选中内容或全文改写为公众号风格。
- 提供标题建议和“去 AI 味”。
- 全文操作前明确展示将发送的内容范围，并要求用户确认。

#### FT-AI-006 无配置状态（P0）

- 未配置模型时，AI 按钮仍可见，但点击后进入配置引导。
- 用户跳过配置后，编辑、预览和导出保持完整可用。
- AI 服务失败不得影响当前文档和本地草稿。

### 8.6 图片处理

#### FT-IMG-001 远程图片（P0）

- 支持 Markdown 中的 HTTPS 图片 URL。
- 预览时显示加载、成功和失败状态。
- 导出前检查图片是否可用于浏览器画布渲染；遇到跨域限制时给出具体提示。
- FasType 不提供图片代理；远程图片需要来源站点允许 CORS，才能可靠导出到 PNG。
- 单张图片失败不应阻塞纯文字页面的编辑和预览。

#### FT-IMG-002 本地与粘贴图片（P1）

- P0 不承诺解析 Markdown 文件旁的相对路径图片，因为浏览器通常没有相邻目录访问权限。
- P1 可支持选择本地图片、粘贴图片，以及配置用户自己的图床。
- FasType 不在 MVP 提供官方图片上传和托管服务。

### 8.7 设置与本地数据

#### FT-SET-001 设置持久化（P0）

- 所有持久化数据只使用 localStorage，不使用 IndexedDB、数据库或远程存储。
- 本地保存当前 Markdown 内容和文件名、小红书主题、公众号主题、公众号封面设置与两张压缩裁剪图、外观、语言、AI 配置、上次视图和三个视图各自的分栏比例。
- 文档草稿与普通设置分开存储，避免清除某类设置时误删正文。
- 提供“导出配置”和“导入配置”，导出时默认不包含 API Key；用户主动选择后才可包含敏感配置。
- localStorage 数据必须带结构版本号；读取到旧版本或损坏数据时安全降级，不能阻止应用启动。
- 文档自动保存使用防抖，避免每次按键都同步写入 localStorage。
- P0 不把原始图片或大型 Base64 内容写入 localStorage；公众号封面仅保留 900×383 与 500×500 两张压缩裁剪结果，并继续受统一配额保护。

#### FT-SET-002 清除数据（P0）

- 用户可以分别清除：当前草稿、平台样式、AI 配置和全部本地数据。
- 清除当前草稿或全部数据前必须明确展示影响范围并二次确认。

#### FT-SET-003 品牌主题与可访问性（P0）

- 支持浅色、深色和跟随系统。
- 品牌主色为 `#0088FF`，辅色为 `#5DB3FF`。两者只用于品牌识别、当前状态、焦点和少量关键交互的点缀，不作为大面积背景、面板色或通用边框色。
- 工作台整体仍以黑、白和中性色为基础；小红书和公众号预览内的内容主题保持独立。
- 主题切换入口直接显示在主工作台顶部，不要求进入设置。
- 主题选择保存在本地，首次访问默认跟随操作系统。
- 所有核心操作可使用键盘完成。
- 关键按钮、输入框和状态不能只依赖颜色表达。

#### FT-SET-004 中英文界面（P0）

- 首版同时提供简体中文和英文界面。
- 首次访问优先读取浏览器语言；不匹配时默认使用中文。
- 用户可以在主工作台直接切换 `中 / EN`，选择结果保存在本地。
- 所有用户可见文案、错误信息、空状态和无障碍标签必须进入统一的 i18n 资源，不能散落硬编码。
- 切换语言不得刷新或清空当前文档、样式和 AI 结果。

### 8.8 可调分栏布局

#### FT-LYT-001 分隔条交互（P0）

- 桌面端三个主视图都使用水平双栏布局；中间分隔条支持鼠标和触控板拖动。内容编辑器内部的“文本 / 预览”不改变分栏。
- 指针悬停时显示左右调整光标和可见的交互反馈。
- 拖动过程中不得误选正文，也不得导致编辑器失焦或丢失未保存输入。
- 双击分隔条恢复当前视图默认比例：Markdown 为 50% : 50%，小红书和公众号为约 33% : 67%。

#### FT-LYT-002 尺寸边界（P0）

- 左右两栏都设置可用的最小宽度，不能被拖到完全不可操作。
- 建议桌面端预览区最小宽度为 280px，编辑区最小宽度为 360px；最终数值可根据视觉实现微调。
- 窗口宽度变化时优先保持比例；不足以满足两侧最小宽度时进入窄屏降级布局。

#### FT-LYT-003 布局持久化（P0）

- 小红书预览、公众号预览、编辑器分别保存自己的分栏比例，互不覆盖。
- 分栏比例在拖动结束后写入 localStorage。
- 刷新页面或重新打开应用后恢复上次比例；数据缺失或非法时恢复该视图默认值。

#### FT-LYT-004 窄屏降级（P0）

- 当可用宽度不足以安全显示双栏时，不继续压缩两侧内容。
- 窄屏下的平台双栏改为“预览 / 编辑”二选一切换，同一时刻显示一侧；右侧内容编辑器仍可独立切换文本与可编辑预览。
- 切换窄屏模式不得修改桌面端已保存的分栏比例。

## 9. 前端技术与架构约束

### 9.1 纯前端边界

- 使用 Next.js App Router 构建，但所有产品能力运行在浏览器端。
- 项目必须支持静态导出和静态站点部署。
- 不使用 Next.js Route Handler、Server Action、服务端数据库、Redis、任务队列和对象存储。
- AI、远程图片、文件读写、剪贴板和本地存储均通过浏览器能力完成。
- 前端不得假设存在同源 `/api` 服务；部署后只需要静态文件服务器即可运行。

### 9.2 前端技术栈

- 使用 **Shadcn/ui** 作为基础组件体系。
- 使用 **Tailwind CSS** 完成布局、主题和样式，不再并行引入第二套 UI 框架。
- 使用 **Lucide** 作为通用图标库；除平台品牌图标外，不重复引入其他通用图标集。
- 使用 CSS 变量承载浅色/深色主题令牌，Shadcn 组件与自定义组件共享同一套颜色、圆角和间距规则。
- 优先复用 Shadcn 的 Button、Input、Dialog、Drawer/Sheet、Dropdown Menu、Tabs、Tooltip、Toast 等基础组件。
- 新组件应保持小而可组合，避免把 LovType 的大型工作台组件整体搬入。

### 9.3 简洁与易用约束

- 主页面只保留一个一级导航：小红书、公众号、编辑器。
- 打开应用后直接进入可编辑状态，不设置登录页、项目首页或强制新手向导。
- 高频操作最多一次点击可达；导出、复制和下载使用清晰的主按钮。
- 只有危险操作、敏感配置和 AI 覆盖正文需要二次确认。
- 图标必须配合 Tooltip 或文字，不能让用户猜测 Lucide 图标的含义。
- 空状态直接提供可执行入口，例如“打开 Markdown”与“开始输入”，避免纯说明页。

### 9.4 浏览器直连模型

- AI 客户端直接对用户的 Base URL 发起 `fetch` 请求，并携带用户 API Key。
- 首版只承诺 OpenAI 兼容的 Chat Completions 协议。
- 必须处理 CORS 预检、超时、主动取消、流式响应不兼容和 HTTPS 页面访问 HTTP API 等浏览器限制。
- 本地模型能否访问取决于其监听地址和 CORS 配置，FasType 只负责检测并给出配置提示。
- 不得为了兼容某个模型临时增加隐藏代理或后端接口。

## 10. 数据、隐私与安全要求

### 10.1 数据边界

| 数据 | 默认存储位置 | 是否发送到外部 |
|---|---|---|
| Markdown 正文 | 浏览器本地草稿、用户选择的本地文件 | 仅在用户主动使用 AI 时发送必要范围 |
| 小红书/公众号样式 | 浏览器本地 | 否 |
| 公众号封面设置与压缩裁剪图 | 浏览器本地 | 否 |
| API Key | 浏览器本地敏感配置 | 仅用于用户主动发起的模型请求 |
| Base URL / 模型名 | 浏览器本地 | 用于连接目标模型服务 |
| 远程图片 URL | Markdown 与浏览器请求 | 浏览器会直接访问该 URL |
| 使用分析 | 默认关闭 | 只有用户明确选择后才可发送匿名数据 |

### 10.2 安全要求

- 禁止在客户端日志、错误上报、URL 参数和埋点中记录 API Key。
- 不得把 API Key 注入渲染后的 HTML、导出图片或下载文件。
- API Key 仅能由浏览器在用户主动发起 AI 操作时发送到其填写的 Base URL。
- API Key 默认只保存在当前设备；界面必须说明浏览器本地存储并不等同于系统钥匙串加密。
- 用户可配置的 Base URL 必须做协议和格式校验，并清楚展示实际请求目标。
- 不引入第三方运行时脚本、远程字体或默认遥测，降低本地 Key 和正文被第三方脚本读取的风险。
- 应在不阻断用户自定义 Base URL 的前提下配置 Content Security Policy；脚本、样式等非连接资源保持严格的同源限制。
- 导入 Markdown 和渲染 HTML 时必须过滤脚本、事件属性及危险协议，避免 XSS。
- 外部链接默认使用安全的打开方式；导出到公众号的内容不得携带应用脚本。

### 10.3 部署模式要求

- MVP 以 Next.js 静态导出为基准部署形态。
- 构建产物可以部署到 GitHub Pages、Cloudflare Pages、Vercel 静态托管、Netlify 或任意静态文件服务器。
- 运行时不依赖 Node.js 服务、数据库、Redis、Celery 或对象存储。
- 本地开发可以使用 Next.js 开发服务器，但它不构成产品后端。
- README 必须明确说明浏览器 CORS、混合内容和远程图片画布限制。

## 11. 异常与边界处理

| 场景 | 预期行为 |
|---|---|
| 打开超大文档 | 提示可能影响性能，允许继续；不得无响应地丢失内容 |
| Markdown 语法错误 | 尽可能渲染其余内容，并定位或提示异常位置 |
| 远程图片失效 | 显示占位，列出失败图片，不阻塞纯文本导出 |
| 小红书某页内容溢出 | 自动重新分页；无法处理时标记具体页面，禁止静默裁切 |
| 公众号复制权限被拒绝 | 提示用户授权，并提供 HTML 下载和纯文本复制 |
| AI 请求超时 | 保留正文与已返回内容，允许取消和重试 |
| API Key 错误 | 不反复自动重试，直接引导检查配置 |
| Base URL 不兼容 | 展示请求阶段和兼容性提示，不泄露 Key |
| Base URL 不允许 CORS | 说明这是目标服务的浏览器访问限制，并给出服务端开启 CORS 的方向 |
| HTTPS 页面调用 HTTP 模型 | 提示浏览器混合内容限制，建议使用 HTTPS API 或在本地运行 FasType |
| localStorage 不可用 | 明确提示无法自动恢复配置和上一次数据，仍允许编辑与下载 Markdown |
| localStorage 配额已满 | 停止继续写入并提示用户立即下载 Markdown；不得覆盖最后一份可读取数据 |
| 新文件覆盖当前草稿 | 必须先处理未保存状态 |
| 浏览器刷新或崩溃 | 尽可能恢复最近一次本地草稿和样式设置 |

## 12. 非功能需求

### 12.1 性能

- 首屏在常规桌面网络与设备下尽量在 2 秒内可交互。
- 10,000 中文字符的常规输入响应目标低于 50ms。
- 内容变化后，普通预览更新目标低于 300ms；复杂图片内容可延迟但必须显示状态。
- 拖动分隔条时以接近 60fps 的流畅度更新布局，避免重复执行昂贵的 Markdown 解析和图片渲染。
- 10 页以内的小红书图片导出应显示逐页进度，单页失败可独立重试。
- 对预览和 AI 请求做防抖、取消和竞态保护，旧请求结果不能覆盖新内容。

### 12.2 兼容性

- 首要支持最近两个主要版本的 Chrome、Edge 和 Safari。
- Firefox 保证基础编辑、预览与下载；文件写回等能力按浏览器支持情况降级。
- 桌面端为 MVP 主形态；窄屏下平台双栏按“预览 / 编辑”单栏切换方案降级，编辑器内部显示方式不改变该布局规则。
- 中文和英文在全部目标浏览器中都必须完成核心流程测试。

### 12.3 可维护性

- Markdown 解析、平台渲染和导出共享基础语义，但小红书与公众号保留独立平台适配层。
- 预览与导出必须复用同一平台渲染配置，避免形成两套样式实现。
- 内置主题使用可版本化的结构化配置，便于社区贡献。
- AI Provider 采用统一接口，首版只保证 OpenAI 兼容协议。
- 业务组件不得直接硬编码中英文文案或主题颜色。

### 12.4 开源要求

- README 必须包含功能截图、快速启动、静态部署方式、AI 直连/CORS 配置说明、数据边界和限制。
- 提供明确许可证、贡献指南、行为准则和安全问题报告方式。
- 示例配置不能包含真实 API Key。
- 默认不开启遥测；未来如加入，必须明确、可关闭并获得用户同意。

## 13. 核心验收标准

### 13.1 单文档闭环

- 用户可以新建或打开一篇 Markdown，并完成编辑。
- 用户打开第二篇文件时，系统会保护第一篇的未保存内容。
- 刷新页面后可以恢复上一次草稿。
- 用户可以保存回文件，或在不支持时下载 Markdown。

### 13.2 小红书闭环

- 当前 Markdown 能生成多页 3:4 卡片预览。
- 修改主题和字号后，所有页面实时更新。
- 长文不会在图片底部静默裁切。
- 导出的 PNG 数量、顺序、内容和预览一致。

### 13.3 公众号闭环

- 当前 Markdown 能生成公众号风格预览。
- 标题、段落、列表、引用、图片和代码块具有可读的降级样式。
- 点击“复制到公众号”后，可在支持富文本粘贴的编辑器中保留核心样式。
- 剪贴板失败时仍可下载 HTML 或复制纯文本。
- 能分别预览并下载 900×383 横版封面与 500×500 方形封面，也能一次打包下载两张图。

### 13.4 AI 闭环

- 用户可以配置 Base URL、API Key 和模型并测试连接。
- 用户选择文本后可以执行至少润色、扩写、精简和自定义操作。
- AI 结果出现后，原文在用户确认前保持不变。
- 替换结果可以撤销；失败和取消不会破坏文档。
- 未配置或 AI 服务不可用时，编辑与导出功能仍正常工作。

### 13.5 隐私闭环

- 不使用 AI 时，编辑和导出不会上传正文到 FasType 官方服务。
- API Key 不出现在 URL、日志、导出文件和错误文案中。
- 清除 AI 配置后，本地不再保留可读取的 Key。

### 13.6 纯前端与双语主题闭环

- 静态构建产物在没有任何业务后端的环境中可以完成编辑、预览和导出。
- AI 请求可以在浏览器网络面板中确认直接发往用户填写的 Base URL，不经过 FasType 域名中转。
- 浅色、深色和跟随系统均可正常使用，刷新后保持用户选择。
- 中文和英文可以即时切换，切换时当前文档与操作状态不丢失。
- 页面通用组件来自 Shadcn，样式基于 Tailwind，通用图标使用 Lucide。

### 13.7 localStorage 与可调分栏闭环

- 输入 Markdown 后刷新页面，能够恢复上一次内容、文件名和所在视图。
- 小红书/公众号样式、AI 配置、语言、主题均能从 localStorage 恢复。
- 编辑器视图首次打开为 50% : 50%，小红书和公众号首次打开约为 33% : 67%。
- 三个视图的分隔条均可拖动，且分别记住各自比例。
- 双击分隔条可以恢复当前视图默认比例。
- 左右两侧均无法被拖到不可操作宽度；窄屏能够切换预览与编辑。
- localStorage 中的数据损坏或超出配额时，现有 Markdown 不会被静默清空。

## 15. 成功标准

首版成功不以注册量或付费转化衡量，主要看核心任务是否简单可靠：

- 新用户无需文档即可完成一次 Markdown → 小红书 PNG 导出。
- 新用户无需文档即可完成一次 Markdown → 公众号富文本复制。
- 已有 OpenAI 兼容服务的用户可以在 2 分钟内完成配置并执行一次 AI 修改。
- 常见文档在预览与导出之间无明显样式和分页差异。
- 非 AI 核心流程不依赖任何外部 FasType 服务。
- 静态部署不需要维护后端服务，用户配置模型后由浏览器直接调用。
- 中文和英文用户都可以完成全部核心流程，浅色与深色主题均无关键可用性问题。
- 用户刷新页面后可以无感恢复上一次 Markdown 和界面布局。
- 社区可以通过新增结构化主题配置贡献样式，而不必修改核心渲染逻辑。

如果未来加入可选匿名遥测，可关注以下漏斗，但默认不得开启：

1. 打开应用 → 首次输入/导入 Markdown。
2. 首次输入 → 打开平台预览。
3. 平台预览 → 成功导出/复制。
4. 打开 AI 配置 → 连接测试成功。
5. AI 请求发起 → 用户接受结果。

## 16. 与 LovType 的边界

FasType 可以参考或复用 LovType 中已经验证的 Markdown 解析、平台渲染、分页导出和微信内联样式思路，但产品模型必须保持独立。下表中的“精简”只裁剪账号、项目、服务端等产品范围；已经保留的主题、排版和预览能力，应尽可能保持 LovType 的视觉与交互细节。

| LovType 能力 | FasType 处理方式 |
|---|---|
| 项目与文件树 | 删除，只保留当前单文档 |
| 多格式文件与云存储 | P0 仅本地 Markdown/TXT |
| 用户、会员、积分、订单 | 删除 |
| 项目 AI Assistant / Agent | 删除，改为轻量文本操作 |
| 后端模型与 Provider 管理 | 删除，改为浏览器本地 BYOK 配置和直连请求 |
| API、Celery 生成任务 | 删除，AI 请求直接在浏览器中同步/流式执行 |
| 小红书发布工作区 | 精简为样式设置、分页预览和 PNG 导出 |
| 公众号发布工作区 | 精简为样式设置、预览和富文本复制 |
| 公共分享 | 删除 |
| 管理后台 | 删除 |
| 中英文完整业务 i18n | 保留中英文能力，但只覆盖 FasType 的精简界面 |

## 17. 已确认产品决策

1. FasType 是 LovType 的轻量开源衍生产品，不追求完整功能范围对齐；已经纳入范围的核心功能应尽可能还原 LovType 的样式和交互。
2. 一次只编辑一个文件，不提供项目和多文件管理。
3. 核心平台为小红书与微信公众号。
4. 用户自行提供 API Key、Base URL 和模型名。
5. AI 是轻量辅助，不引入 Agent 和复杂生成任务。
6. 项目是纯前端 Next.js，不建设任何业务后端，AI 由浏览器直接调用用户 Base URL。
7. 无账号、本地优先，支持静态部署。
8. 继续使用 Shadcn、Tailwind 和 Lucide。
9. 首版支持浅色/深色主题以及中文/英文界面。
10. 小红书以 PNG 结果为核心；公众号以富文本复制结果为核心。
11. 所有配置与上一次文档数据统一保存在 localStorage，不使用 IndexedDB。
12. 小红书排在首位并作为默认视图，公众号居中，编辑器排在最后；小红书和公众号默认使用约 1:2 的成品预览 / 工作台双栏，“内容”编辑器工具栏最右侧可切换文本与可编辑 Markdown 预览；编辑器主视图保持默认 1:1 双栏。

## 18. 待确认事项

以下事项不阻塞基础工作台设计，但需要在对应 Milestone 开始前确认：

1. **开源协议**：MIT、Apache-2.0 或其他协议。
2. **品牌关系**：FasType 是否在界面与 README 中明确使用 “LovType Open Source” 副标题。
3. **小红书首版深度**：P0 是否必须包含独立封面页和手动分页。
4. **公众号模板深度**：首版提供基础主题，还是同步移植 LovType 的高级元素级设置。
5. **图片策略**：P1 优先支持本地图片、用户自有图床，还是两者同时支持。
6. **模型兼容范围**：首版只承诺 OpenAI Chat Completions，后续是否兼容 Responses API、Anthropic 与 Ollama 原生协议。
